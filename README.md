# robust_child_filtering_model

Course project (Programming for Deep Learning): a child-or-adult filtering model that is as accurate for Black teenagers as for White teenagers.

Automated child detectors used to filter text-to-image training data (Crețu et al., IEEE S&P 2026) miss Black teenagers more often than White teenagers. Our preregistered audit ([child-skintone-detection](https://github.com/isaacmutuma/child-skintone-detection), Phase 1) measured gaps of 4.0 to 10.0 percentage points on UTKFace, concentrated in ages 10 to 17. This project trains age models on frozen CLIP ViT-L/14 embeddings with fairness-aware methods, then fine-tunes CLIP itself, to test whether the gap can be closed without raising false positives on adults and without race at filtering time.

**Status (2026-11-26):** embeddings and folds done; model A (gap 0.110 [0.077, 0.142]) and B, C, C2 under the final tuning rule v3 done, none closes or narrows the gap (`results/`). Model E-invariant (adversarial, notebook 06) run on 19 Nov: gap 0.106 [0.071, 0.137], reduction vs A 0.004 [-0.017, 0.024], outcome neither; the adversary was driven to chance but a fresh probe still reads race from its representation as well as from A's (balanced accuracy 0.816 vs 0.819, chance 0.20). Follow-up 1 (notebook 07, `docs/FOLLOWUP_E_FORCE_RACE.md`): pushing the adversary up to lambda 10 never removed race from the representation (probe 0.81-0.82) and never significantly narrowed the gap. Follow-up 2 (LEACE concept erasure, notebook `08_LEACE.ipynb`): removing all linear race information from the embeddings (linear probe at chance, 0.200) left the gap at 0.100 [0.067, 0.132] and the Black − White over-estimation at +1.94 years; race stays readable non-linearly (MLP probe 0.81). Model F (LoRA inside CLIP's last 1 or 4 blocks, rerun 26 Nov with fp16 loss scaling): F1-1 gap 0.107 [0.075, 0.138], F1-4 0.115 [0.083, 0.147], F2 (+ adversary) 0.103 [0.071, 0.133]; reductions vs A −0.003, −0.011, +0.001, all CIs include 0; Holm p 1.0 for E, F1-1, F1-4 and F2. Follow-up 3 (`scripts/followup_layers.py`, `docs/FOLLOWUP_LAYERS.md`): reading age from every block of frozen CLIP shows the gap (89% of final) and the Black − White over-estimation (168%) already present at block 20, where F starts, so F could only adjust a bias it was handed. Follow-up 4 (`scripts/followup_fairface_data.py`, `docs/FOLLOWUP_FAIRFACE_DATA.md`, screening): adding all 86,744 FairFace training faces to the age head (interval loss on its age bins) did not narrow the gap (0.112 vs 0.105 for A rebuilt in the same run; MAE 4.41 -> 4.33); 25% -> 100% of UTKFace moved the gap only 0.119 -> 0.105, and a FairFace-only model shows the same gap (0.102) and over-estimation (+2.02), so more data does not fix it and the existing experiments stand. The course submission is built in `notebooks/submission/DLP_term_project.ipynb`. ## How to reproduce (course submission)

**Main file:** `notebooks/submission/DLP_term_project.ipynb` (built by `scripts/build_submission_notebook.py`). It is self-contained: it downloads the data and weights, computes the CLIP features, builds the folds and trains every condition.

**Run it:** open it in Google Colab (Runtime → Change runtime type → T4) or in Jupyter on a GPU server (set `GPU_ID` in the setup cell), then Run all. Each part has an on/off switch in `RUN`. Approximate time on a T4: data + CLIP features 25 min, A 5 min, E 90 min, follow-up 1 60 min, follow-up 2 25 min, follow-up 3 about 15 min on an A5000 (or loads the saved result), each F condition a few hours (`notebooks/10_model_F.ipynb` / `docs/RUN_F_ON_SERVER.md` time one fold first).

**Packages:** Python 3.11+, PyTorch 2.x with CUDA, `open_clip_torch==3.3.0`, `huggingface_hub`, `numpy`, `pandas`, `scikit-learn`, `matplotlib`, `Pillow` (Colab has all except open_clip, which the notebook installs).

**Data and checkpoints (downloaded and checked automatically):**
- UTKFace: `py97/UTKFace-Cropped` @ `e80f21fb`, file `UTKFace.tar.gz`, SHA-256 `2c065539…`; 23,705 usable images (3 malformed file names skipped).
- CLIP ViT-L/14, OpenAI weights: `timm/vit_large_patch14_clip_224.openai` @ `18d05354`, SHA-256 `9ce2e8a8…`, loaded with QuickGELU (checked).
- ICCWD (only for Section 10): labels `amcretu/iccwd` @ `9f76b200`; images fetched from their original URLs with the authors' script (`notebooks/09_iccwd_fetch.ipynb`), kept on Google Drive, never in git.

**Run it on the course GPU server (unattended):** `bash scripts/server_submission_run.sh <GPU_ID> "<demo image numbers>"` fetches ICCWD with the dataset authors' pinned script into a temporary folder, executes the notebook (re-check and ICCWD on; F and follow-up 3 load their saved results), writes the executed notebook to `~/submission/` (outside the repository, because it shows the demo photos), and deletes the ICCWD copy afterwards. Progress: `bash scripts/server_submission_status.sh`.

**Experiment log:** Section 12 of the notebook (settings, epochs, updates, batch size, seed, run time and device for every run); the aggregate result files with their git commit are in `results/`.

**Layout:** `configs/config.py` (paths, pins, frozen constants) · `src/` (CLIP loader with QuickGELU check, data, folds) · `scripts/` (Colab steps) · `notebooks/` · `results/` (aggregate JSON only) · `tests/`.

**Ethics:** no images of children are generated; only UTKFace and FairFace are used; images, embeddings and per-image outputs never enter git; figures and the demo show charts only.
